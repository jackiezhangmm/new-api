# 无限画布集成路线图

## 目标与状态

在尽量保留 infinite-canvas 既有图片画布交互与工程结构的前提下，明确接入 new-api 登录认证、模型 Relay、云端工程、精选词库和数字资产所必需的差异，形成可实施的集成方案。

规划已收敛，可进入实施：产品范围、复用原则、认证与模型接入方向及工程云端存取行为均已确认。具体模型名单、接口与存储结构、更新检查方式和协议适配验收在实现阶段完成。本文不表示集成已经实现或通过验收。

## 已确认方向

### 复用上游交互

- 默认保留上游已有的画布操作、资产选择、资产插入与节点收录体验，只调整本站接入所必需的部分。
- 资产库接入重点是替换本地数据源、映射数据结构和接入用户权限，不重新设计拖拽或双向交互协议。
- 工程持久化沿用上游工程文档结构，按保留的能力保存必要内容，不重新定义一套画布内部模型。
- 功能范围约束用户可见能力；具体代码裁剪必须依据依赖关系，不以文件名或删除清单代替分析。

### 首期产品范围

- 在 new-api 的“AI 应用”中提供画布入口，保留主站导航；画布提供中文界面。
- 聚焦图片画布，不开放视频、音乐及独立 Agent 工作流；不提供图片超分能力。
- 用户无需配置 API Key、Base URL 或外部同步服务，模型请求通过本站 Relay 调用并沿用本站计费。
- 提供经验证的受控图片模型集合；提示词修饰、图片反推等辅助能力使用固定 LLM，具体名单在实现阶段维护。
- 精选词库使用本站数据，个人资产使用本站数字资产，不依赖外部词库作为本站精选内容来源。

### 认证与模型接入

- 主站已登录的用户打开内嵌画布即可使用，无需再次登录或配置。主站管理登录、会话刷新和退出，画布通过小型宿主接口取得有效认证头，直接请求本站 Relay，并保留请求取消及流式结果处理。
- 复用主站已有会话能力，不在画布另建认证体系。会话失效交由主站统一处理；认证凭据仅供运行时请求使用，不写入画布配置、工程或本地持久化。
- 面板 Access Token 通过 `Authorization` 携带，不作为上游通用 API Key 配置；不同模型协议统一接入本站会话认证。具体宿主接口形式在实现阶段确定，按同域受信任子应用设计，不将同域内嵌视为安全隔离。
- 独立维护画布模型与能力配置，定义允许的操作、参数范围和请求协议；不自动继承作图广场全部模型。作图广场已有实践作为候选与复用依据，具体名单和辅助 LLM 选择不阻塞初期规划。
- 能力配置同时驱动界面和发送前校验，结合用户实际可用模型决定可执行范围。打开已有工程也校验其模型和参数，不因旧数据绕过限制；模型不可用时明确提示，不擅自换模型执行。
- 受控名单是画布的产品范围，不是新增的服务端授权规则。本站 Relay 继续执行用户原有权限、分组及计费规则，不改变用户在其他 AI 应用或 API 中的权限。
- 保留上游操作入口、交互流程及可复用的请求构造与解析，在必要位置适配本站认证与协议。实现阶段逐项验证后开放能力，不复制整套作图广场，也不预先建设全站通用 AI 调用框架。

### 工程云端存取

- 长期定位为在线应用，不支持离线使用。云端是工程的唯一正式保存位置，按用户隔离；保留上游创建、打开、导入、重命名、删除和编辑体验。
- 修改后空闲时自动保存，只有服务端确认后才表示保存完成。短暂断网时保留当前页面内容并提示未保存，恢复连接后尝试保存；不承诺关闭页面后恢复未保存修改，离开前给予提醒。
- 用户回到已打开的画布时检查云端更新；没有未保存修改或进行中的工作需要保护时，自动跟进最新工程，不让普通的跨设备使用变成冲突处理。具体检查与协调方式保持简单，在实现阶段确定。
- 本地未保存修改与云端更新冲突时，保留本地内容并停止自动覆盖，允许另存为新工程，或放弃本地修改并打开云端版本；首期不提供强制覆盖或自动合并。
- 云端已删除的工程不因旧页面保存而复活；有本地未保存内容时可另存为新工程，否则提示删除并返回列表。
- 正常的连续编辑、自动保存和图片生成结果不应相互覆盖，也不应制造需要用户处理的冲突。

### 图片上云

- 生成结果、本地导入、粘贴、裁剪和分割产生的图片统一上云。
- 云端图片独立于数字资产。上传不自动收录；“存入资产”仅创建对已有云端图片的资产条目。
- 记录图片身份和存储信息，画布与图片资产通过图片 ID 使用图片；从已有图片资产加入画布时复用对象。
- 首期删除节点、画布工程或图片资产均不删除对应云端文件，不额外维护引用表、引用计数或回收任务。
- 接受云端图片持续占用存储、可能存在遗留对象的代价；未来有实际需要时再设计回收和存量关系重建。
- 上传、保存失败如实提示，不将失败标记为已同步；首期不建设完整的未同步草稿恢复体系。
- 使用公开读 S3，精选词库与云端图片复用通用存储能力。图片身份和写入操作仍须按用户授权；公开读不等于私密文件存储。

### 工程组织与交付

- 画布源码纳入根目录 `canvas/`，与 `web/` 独立依赖、独立构建，同仓提交、统一发布，不使用 Git Submodule。
- 控制台入口为 `/playground/canvas`，以同域子应用形式接入，复用主站认证能力。
- 子应用制品装配到 `web/dist/canvas/`，复用现有 Go 静态托管和发布流程；正确区分页面路由兜底与缺失静态文件的 404。
- 扩展现有 `makefile`、Docker 和开发编排，覆盖资源路径、开发代理及热更新，不另建一套交付流程。
- 体积与缓存按现有构建能力及实际验收结果处理，没有测量依据时不设独立优化规划。

## 分阶段实施与验收

### 拆分结论与行数口径

不建议把“认证与全部模型”“工程上云”“图片上云”各做成一个 800–1200 行的提交。上游的协议分支、工程同步竞态和图片来源数量，决定了这三个主题都需要继续拆分。

推荐顺序为：**应用装配 → 产品范围与宿主认证 → 最小图片生成 → 图片云端身份与全入口覆盖 → 工程云端保存与同步 → 图片编辑和辅助模型 → 精选词库与数字资产。**

先完成图片身份再把工程云端保存开放给用户，避免出现“工程已保存，换设备图片却丢失”的中间产品。工程服务端可以并行准备，但工程上云阶段不能跳过图片依赖验收。图片编辑、辅助 LLM 和资产库不阻塞最小生成与保存闭环，放在后面逐步开放。

行数采用以下口径：

- 每个 M 阶段对应一个可独立审阅、可验收的集成 diff；新增行与删除行相加，不看净增长。测试、翻译、文档及手写配置均计入。
- 800–1200 行是实施参考预估，不是硬性考核的工作量；不为凑数增加抽象或测试。当变动较大时，重点在于审阅交付边界是否合理，保证验收必需的失败路径与可靠性。
- 独立列出锁文件、自动生成文件与原样上游源码的行数，不把它们伪装成零成本。避免通过压缩代码、搬进生成文件拆分代码。
- **源码首次入库为特殊场景，需实施前确认。** 当前仓库没有 `canvas/` 源码；`infinite-canvas-dist/` 是制品目录，不是源码集成。临时目录中的完整上游应用有数万行，仅画布交互主体也远超千行。建议用独立的 `V0` 原样源码基线提交，记录提交号、来源和许可证，不夹带功能改动；后续 M 阶段按常规规模递进。V0 不计作一个已交付功能阶段。
- 避免将完整应用机械切成十几个不能运行的搬运阶段。
- 大规模删除上游未使用实现同样计入 diff，不承诺塞进某个收尾阶段。首期先封闭路由、能力注册和执行入口；可保留不可达历史代码。确有必要的物理删除另列审阅，不以“清理”为名扩大某个阶段。

### 开发验收规则

- 从 M0 开始统一从主站 `/playground/canvas` 进入。日常人工验收使用 `make dev` 的默认 `http://127.0.0.1:5173/playground/canvas`；正式制品验收使用 `make preview` 的 `http://127.0.0.1:5174/playground/canvas`。
- M0 即接通开发代理、画布热更新及正式构建装配；不能到最后才发现 iframe、资源路径或 Cookie/会话刷新只能在独立开发服务器中工作。
- 未完成的能力不显示为可用，旧工程也不能通过遗留配置触发。M0 至 M4 为集成预览，不对外承诺工程已云端保存；页面明确说明当前保存限制。默认不向普通用户开放半成品入口。
- PostgreSQL、Redis 使用隔离的开发/预览环境。准备两个普通账号 A/B、A 的两个浏览器会话、一个可用图片模型、一个辅助 LLM、公开读 S3 测试前缀及必要 CORS。真实生成会消耗额度，使用测试账号并记录消耗日志。
- 每阶段运行受影响包测试和画布类型检查/构建；涉及主站装配时执行 `make build-web`。数据库迁移、并发写入和所有权校验必须在 PostgreSQL 验证。发布前执行 `make test` 与 `make preview`。
- 人工验收负责真实交互、S3 CORS、会话和协议；自动化测试负责可确定重现的竞态及异常。不能用“手动同时点击”代替保存乱序、旧生成结果晚到等回归测试。
- 验收记录只写实际运行的命令和结果。本节来自静态源码阅读，并不表示以下阶段已构建、已联调或已通过浏览器验收。

### M0：应用接入与统一交付

**范围**：独立 `canvas/` 包及资源基路径、主站认证路由内的承载页面、AI 应用入口、Go 静态托管、makefile、Docker、开发及预览编排。优先保留上游源码布局，避免无关文件移动和格式化。

**边界**：本阶段只开放画布基本操作用于预览，模型、外部服务配置及不在首期范围内的页面不得因原样引入而对外开放。M1 完成运行时能力封闭；这里先保证可见和直达路由入口均受限。不在 M0 同时实现认证刷新桥、模型适配和工程同步。

**人工验收**：

1. 已登录用户从主站进入，主站导航保留；未登录访问仍由主站处理。
2. 新建预览工程，添加文本/图片节点、拖动、缩放和连线可用；不显示“已云端保存”。
3. 修改画布源码可热更新，主站其他 AI 应用不受影响。
4. `make preview` 中刷新主站画布入口、打开工程内部页面均正常。
5. `/playground/canvas` 返回主站承载页面；子应用页面由 `/canvas/` 下约定的页面路由加载。缺失的 `/canvas/assets/not-found.js` 返回 404，而不是任一应用的 HTML。不要把主站画布路由直接替换成子应用 HTML 导致导航消失。

**自动验收**：页面兜底与缺失静态资源的 HTTP 契约；独立构建及统一制品中画布资源存在。

**M0 实施记录**：对应提交 `46930a10`。已完成 `canvas/` 子应用纳入同仓、`/playground/canvas` 主站认证路由入口、`/canvas/` 子应用资源基路径、Go 静态托管与页面兜底、主站与画布独立开发服务器及代理、`make build-web`/Docker 统一构建装配。画布开发服务器使用 3001 端口，主站开发服务器使用 5173 端口；正式制品装配到 `web/dist/canvas/`。后续 M1 修复了画布路由运行时导入遗漏，但不改变 M0 的交付边界。

### M1：宿主认证与首期能力边界

> 本阶段“关闭”统一表示用户触达不到：关闭相关入口、路由、能力注册和执行路径；核心代码保留，不为此进行大规模物理删除。项目安全性要求较低，用户切换以可见数据隔离为准，不额外引入清除缓存、复杂加密或完整本地数据生命周期管理，以节省流量并保持实现简单。

**范围**：小型宿主接口获取有效认证头，刷新/失效/退出交由主站；固定中文；限制为图片画布，关闭视频、音乐、独立 Agent、超分、用户 API Key/Base URL、WebDAV、代理和任意模型插件入口。关闭导入和导出能力。

**关键边界**：不仅隐藏菜单，还限制路由、导入的节点类型、能力注册和发送入口；“关闭”以用户不可触达为准，核心代码可以保留，不大批删除历史代码。导入和导出入口及相关路由均不可触达。仅接入认证消费接口，不另造一套 Token 存储/刷新状态机。不同账号切换须隔离用户态可见数据，不能读出上一用户的本地工程/资产缓存；在安全性要求较低的前提下，不要求清除本地数据，以避免额外流量和复杂度。

**人工验收**：

1. 打开画布不二次登录、不要求配置；可通过现有用户模型接口验证会话已接通。
2. Access Token 过期后请求由主站刷新恢复；明确退出后画布不能继续请求。
3. A 退出、B 登录，画布不残留 A 的可见内容；本地数据可以保留，但必须按用户态隔离，不能因切换直接展示 A 的工程或资产。
4. 检查画布配置、IndexedDB 和工程导出：没有宿主认证凭据。主站已有认证存储不在此重构。
5. 直达隐藏页面、导入含视频/Agent/外部配置的工程、导入导出入口，均不能执行或触达受限能力；已有图片交互保持可用。

**自动验收**：认证刷新/退出契约、凭据不进入子应用持久化、导入与程序调用的能力限制。具体请求中断由 M2 验证。

**范围**：空闲自动保存、当前编辑版本与已确认版本、单工程串行提交、保存中继续编辑的后续保存、失败提示与恢复重试、离开提醒。复用 M5 冲突底线，不重做工程 API。

**关键边界**：旧保存成功只能确认它提交的版本，不能把随后修改标为干净；自动保存响应不能整份覆盖当前画布。生成和上传完成是正常编辑，使用同一保存通道。未上传图片不进入“已保存”文档。

**人工验收**：

1. 连续编辑后停顿，自动出现保存中、已保存；刷新得到最后内容。
2. 慢网络下保存期间继续输入、移动和生成，最终云端包含所有有效修改，无正常操作导致的冲突弹窗。
3. 断网后保留画布并显示未保存，恢复后保存；断网离开有提醒。
4. 编辑中退出账号或换工程，旧请求不能把新工程/新账号界面标为已保存。

**自动验收**：使用可控制完成时机的请求测试，验证保存排队、旧确认、失败重试、上传与保存协调；不用 sleep 猜竞态。

### M7：跨设备更新与冲突完整体验

**范围**：返回页面时检查云端 revision；没有未保存修改或进行中工作时自动更新；存在本地修改时停止覆盖，另存为新工程或放弃本地打开云端；补齐云端删除时的分支。

**关键边界**：正在生成/上传也属于需要保护的工作，即使文档暂时没有 dirty 标记也不能直接替换。版本检查与自动保存需要协调，不能把本页刚保存的版本误判成其他设备冲突。不增加协作订阅、自动合并或强制覆盖。

**人工验收**：

1. A 的两页打开同一工程，第一页面保存；第二页无修改，切回后自动看到更新。
2. 第二页有修改或生成/上传尚未完成，云端更新不能覆盖当前内容。
3. 发生冲突后分别验证另存和放弃本地；普通重试不应越过冲突继续写。
4. 云端删除：无本地工作返回列表；有未保存内容允许另存，原 ID 始终不会复活。

**自动验收**：返回检查与保存交错、生成保护、删除与保存交错、另存不改原工程、放弃本地后的晚到任务隔离。
